## Branching Strategy
We use **trunk-based development with short-lived feature branches**, reviewed via pull request before merging into `main`. This keeps merge conflicts to a minimum while working in parallel, keeps process overhead low for a 10-week project, and still lets us use PRs and issues for review and planning.
